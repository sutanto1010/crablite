Single binary (`crablite`, Rust 2024 edition) organized into three layers:
- Entry point `src/main.rs` bootstraps tracing via `tracing-subscriber` with `EnvFilter`, loads `.env`, constructs a shared `AppState`, wires the Axum `Router` with `/api/health` plus nested `/api/*` routes (`/connect`, `/db-files`, `/tables`, `/query`, `/correct`) guarded by an `x-api-key` middleware, serves static frontend from `dist/` via `ServeDir::new("dist")`, and binds on `0.0.0.0:PORT`.
- Shared mutable state lives in `state.rs` as a `Clone`able `AppState { db: Arc<RwLock<Option<SqlitePool>>>, db_dir: PathBuf }`, giving handlers concurrent read access to the active pool while only `connect_db` writes it.
- Request handlers are split by concern under `handlers/`: `connection.rs` (WAL-enabled `SqlitePool` setup, recursive `.db` file scanning, table listing), `query.rs` (SELECT vs DML dispatch via `fetch_all`/`execute` with typed row serialization through `serialize_row`), `ai.rs` (schema introspection via `pragma_table_info`/`pragma_foreign_key_list` + sample row, then LLM call via `reqwest`), and `health.rs`. `handlers/mod.rs` re-exports handler functions for `main.rs`.
- Dependency direction is one-way: handlers → `state::AppState`; no ORM layer — all persistence uses raw `sqlx` queries against SQLite with PRAGMA introspection for column metadata.
