## Approach

This monorepo manages dependencies for two independent subprojects using their native package managers:
- **Backend (Rust/Axum)**: `Cargo.toml` declares crates; `Cargo.lock` pins exact versions.
- **Frontend (SolidJS/Vite)**: `package.json` declares npm packages; `pnpm-lock.yaml` is the lockfile, and `pnpm-workspace.yaml` enables workspace mode.

Automated version updates are configured through GitHub's Dependabot, which targets both ecosystems on a monthly cadence against the `dev` branch.

## Key Files

- `backend/Cargo.toml` — Rust dependency manifest. Declares runtime deps (`axum`, `tokio`, `sqlx`, `tower`, `tower-http`, `tracing*`, `clap`, `reqwest`, `dotenv`, `serde*`) with caret or exact version ranges. No `[patch]`/`[replace]` sections and no custom registries are present.
- `backend/Cargo.lock` — Generated lockfile pinning every transitive crate to an exact revision.
- `frontend/package.json` — Frontend manifest. All dependencies live under `devDependencies` (the build toolchain Vite/Solid/Tailwind/DaisyUI compiles assets at build time); no runtime `dependencies` section. The `packageManager` field pins pnpm `10.32.1` with a sha512 integrity hash, enforcing reproducible installs.
- `frontend/pnpm-lock.yaml` — Lockfile generated by pnpm.
- `frontend/pnpm-workspace.yaml` — Enables pnpm workspace mode (no additional workspace members are declared in the file shown).
- `.github/dependabot.yml` — GitHub Dependabot configuration scanning both `backend` (cargo) and `frontend` (npm) directories monthly, opening PRs against `target-branch: dev`.

## Architecture and Conventions

- **Dual-package-manager strategy**: Each language ecosystem uses its canonical manager — Cargo for Rust, pnpm for Node. There is no shared root manifest; each subproject owns its own dependency graph.
- **Lockfiles committed**: Both `Cargo.lock` and `frontend/pnpm-lock.yaml` are checked in, ensuring deterministic builds across environments.
- **Workspace-mode frontend**: `pnpm-workspace.yaml` is present even though only one frontend project exists, allowing future sibling packages to be added without changing install commands.
- **Dev-only frontend deps**: The frontend places all packages (including Tailwind, DaisyUI, SolidJS, TypeScript, Vite) under `devDependencies`. This means the production container image can avoid shipping the full Node toolchain if desired.
- **Release optimization in Cargo**: `backend/Cargo.toml` configures `[profile.release]` with `strip = true`, `lto = true`, and `codegen-units = 1` to minimize binary size and maximize performance — not a dependency declaration per se, but part of how the Rust dependency graph is consumed at build time.
- **No vendoring**: Neither Cargo nor pnpm are configured to vendor third-party sources into the repo. Dependencies are fetched from crates.io and the npm registry at build/install time.
- **No private registries or auth**: No `Cargo.toml` `[registries]`/`[source]` blocks and no `.npmrc`/`.pnp.cjs` files are present, so public registries are used as-is.

## Dependabot Automation

`.github/dependabot.yml` defines two update jobs:

| Ecosystem | Directory | Schedule | Target Branch |
|-----------|-----------|----------|---------------|
| cargo     | `backend` | monthly  | `dev`         |
| npm       | `frontend`| monthly  | `dev`         |

Both use default Dependabot settings (no custom versioning strategy, no ignore rules, no reviewers). Updates open pull requests against `dev`, not `master`, keeping the main branch stable until changes are reviewed.

## Constraints and Rules

- **pnpm version pinning**: `package.json` includes a `packageManager` field with a pinned pnpm version plus a sha512 checksum. This enforces that anyone running `pnpm install` uses the exact verified version of pnpm, preventing lockfile drift caused by different pnpm releases.
- **Dependabot target branch**: All automated update PRs are directed to `dev` (see `.github/dependabot.yml` lines 12 and 17), so dependency bumps land on a dedicated branch rather than directly on `master`.
- **Monthly cadence**: Dependabot runs once per month for both ecosystems (lines 11 and 16), reducing noise from frequent upstream releases.
- **No ignored versions**: The Dependabot config contains no `ignore` entries, so all minor/patch updates are accepted automatically within the semver ranges declared in manifests.
- **No custom registries**: Absence of `[registries]` in `Cargo.toml` and absence of `.npmrc`/`.pnp.*` files means both ecosystems rely on the default public registries (crates.io and npmjs.org).
